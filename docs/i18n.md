# Translations

inua's text is English at its source and translated through gettext
catalogs, keyed by the English: one `.po` file a language in
`internal/i18n/locales/`, embedded in the programs. The shell, settings, light apps, assistant,
games and desktop launchers support Simplified Chinese (`zh_CN`),
Traditional Chinese (`zh_TW`), Japanese (`ja`), Spanish (`es`), French
(`fr`) and Korean (`ko`). English remains the source language.

## The language

Settings → Appearance → Language chooses it: `language` in
`~/.config/inua/config.toml`, one of `auto`, `en`, `zh_CN`, `zh_TW`,
`ja`, `ko`, `es`, `fr`. The programs read it once, at start; after a
change the settings window offers to restart the shell, and open apps
change when they are opened again.

With `auto`, the default, the programs follow the environment as gettext
does: `LANGUAGE` (a list, `fr:de`), else `LC_ALL`, `LC_MESSAGES`, `LANG`.
`zh`, `zh-CN` and `zh-Hans` select Simplified Chinese; `zh-hant`,
`zh-TW`, `zh-HK` and `zh-MO` select Traditional Chinese. Korean uses
`ko`; `kr` is accepted as an alias. Regional locales such as `ja_JP`,
`es_ES`, `fr_FR` and `ko_KR` use their language catalog. An unsupported
language, or English, leaves the text as written. To try one:

```sh
LANGUAGE=zh_CN inua-apps system-monitor
```

## Marking text

In Go (`internal/i18n`):

- `i18n.T("Pause")`: a message.
- `i18n.Tf("Process %d has ended.", pid)`: a format, filled in. A
  translation may take the arguments in another order: `%[2]s … %[1]d`.
- `i18n.Nf("%d core", "%d cores", n, n)`: the form for n, filled in.
- `i18n.M("Resident")`: marks a string kept in a table, or passed on, and
  leaves it as it is; `i18n.T` translates it where it is shown. A string
  that is also a key (a map's) keeps its English there.

Use `i18n.Time(t, "Jan 2 15:04")` for displayed dates. It translates
the layout and the actual month and weekday names. Translate layouts
using Go’s reference date (Mon Jan 2 15:04:05 2006), such as
`1月2日 15:04`. Keep `time.Format` for filenames, protocol values
and other machine-readable dates.

Keep whole sentences in one message, with their numbers and names as
arguments, not joined from pieces: word order differs between languages.

In Blueprint layouts, `_("Filter by name, PID or user")`: the compiled
`.ui` marks it `translatable="yes"`, and `gtkx.Load` translates it before
GTK reads the layout.

## Updating the catalogs

```sh
make i18n
```

gathers every marked string into `po/inua.pot`, the template, and brings
each catalog up to date with it: new messages added untranslated (an empty
`msgstr`), gone ones dropped, translations kept. It also extracts `Name`, `Comment`, `GenericName`
and `Keywords` from `config/apps/*.desktop` and regenerates their
localized fields. Keep the semicolons that separate desktop keywords.
CI fails when the
template or a catalog is out of date. Commit both with the change that
marks the text.

## Adding a language

Copy the template's header into `internal/i18n/locales/LANG.po` with the
language's `Language:` and `Plural-Forms:` (`nplurals=1` for languages
without plurals, such as Chinese and Japanese; two forms, singular for 1,
otherwise; French uses `plural=(n > 1)`), run `make i18n`, and fill in each `msgstr` (`msgstr[0]`,
`msgstr[1]` … for plurals). A translation marked `#, fuzzy` is not used.
The tests check that each translation takes its message's arguments.

## Translation scope

Third-party app names, notification content, remote release notes and
service error details remain in the language supplied by their source.
City-specific lettering drawn into game artwork stays in the city's language.

New catalogs were started with machine translation. Common interface terms,
date layouts and format placeholders have been checked; native-language
review of longer help text is still welcome.
